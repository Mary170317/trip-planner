## Краткое выступление (2–3 минуты)

Здравствуйте! Мой проект называется «Планировщик поездок». Его задача — помочь пользователю организовать путешествие: указать даты, бюджет и план мероприятий.

Серверная часть разработана на Python с FastAPI. Для хранения информации используется SQLite, для работы с таблицами — SQLAlchemy 2.0, а для изменения структуры базы данных — Alembic. Интерфейс создан на HTML, CSS и JavaScript.

Пользователь может зарегистрироваться, войти, создать поездку, изменить или удалить её, добавить события на определённые дни, указать место и примерную стоимость. Реализованы поиск, фильтры, сортировка, статистика и выгрузка CSV.

Важный аспект — защита данных. Пользователь видит только собственные поездки. Пароли не хранятся в открытом виде: применяется хеширование с солью. Административные запросы доступны только пользователям с соответствующим признаком.

Таким образом, проект демонстрирует работу REST API, реляционной базы данных, авторизации и взаимодействия клиента с сервером. Спасибо за внимание!

## Что показать на демонстрации

1. Главную страницу, регистрацию и вход.
2. Создание поездки с названием, датами и бюджетом.
3. Добавление двух пунктов плана на разные дни.
4. Изменение статуса и редактирование поездки.
5. Поиск, сортировку и статистику.
6. Экспорт CSV.
7. Swagger по адресу `/docs`.
8. Пример защиты: попытка открыть чужую поездку возвращает 404.

## Вопросы преподавателя

**Почему FastAPI?** Быстрое создание API, типизация, автоматическая документация OpenAPI.

**Зачем SQLAlchemy?** Удобная работа с таблицами как с Python-классами, безопасное формирование запросов.

**Зачем Alembic?** Версионирование изменений структуры БД без ручного пересоздания таблиц.

**Что такое CRUD?** Create, Read, Update, Delete — создание, чтение, изменение, удаление.

**Что такое внешний ключ?** Поле, ссылающееся на запись другой таблицы и поддерживающее связи.

**Как защищены чужие поездки?** Во всех пользовательских запросах проверяется owner_id по идентификатору из сессии.

**Как хранится пароль?** В виде PBKDF2-SHA256-хеша с индивидуальной солью.

**Как рассчитывается статистика?** Агрегатными SQL-функциями COUNT, SUM, AVG и группировкой по месяцу.

**Что можно улучшить?** Добавить карты, совместные поездки, вложения, уведомления, автоматические тесты и развёртывание с HTTPS.
