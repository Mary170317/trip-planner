# Отчёт по учебному проекту

**Тема:** «Планировщик поездок» (вариант №9)  
**Выполнила:** Усмонова Марямхон Бахтиёрджоновна  
**Группа:** ИСиП1-9-24

## 1. Цель работы
Разработать веб-приложение для организации личных путешествий с возможностью вести список поездок, планировать мероприятия по дням и оценивать бюджет.

## 2. Использованные технологии
- **FastAPI** — REST API и валидация HTTP-запросов.
- **SQLAlchemy 2.0** — объектно-реляционное отображение и запросы к БД.
- **SQLite** — хранение пользователей, поездок и пунктов плана.
- **Alembic** — управление миграциями схемы базы данных.
- **Pydantic** — проверка данных и формирование ответов.
- **HTML/CSS/JavaScript** — адаптивный клиентский интерфейс без фреймворков.

## 3. Модель данных
**users:** id, username, password_hash, is_admin, created_at.  
**trips:** id, owner_id, title, description, start_date, end_date, budget, is_completed, created_at.  
**plan_items:** id, trip_id, title, day_date, time_text, place, estimated_cost, is_done.

Связи: один пользователь → много поездок; одна поездка → много пунктов плана. Внешние ключи обеспечивают целостность данных, а удаление поездки удаляет связанные пункты.

## 4. Реализованные функции
1. Регистрация и авторизация с безопасным хранением паролей.
2. CRUD-операции с поездками.
3. CRUD-операции с пунктами маршрута.
4. Поиск, фильтрация по статусу, сортировка, пагинация.
5. Агрегатная статистика: количество поездок, сумма и средний бюджет, помесячные показатели.
6. Экспорт списка поездок в CSV.
7. Административный просмотр пользователей и поездок.

## 5. Защита данных
Все обычные запросы ограничены текущим пользователем. ID пользователя берётся из серверной сессии, а не из клиентского JSON. При отсутствии прав API возвращает 401/403/404. Пароли защищены PBKDF2-HMAC-SHA256 с уникальной солью.

## 6. Порядок запуска
Создать виртуальное окружение, установить зависимости из requirements.txt, задать SECRET_KEY, выполнить `alembic upgrade head`, запустить `uvicorn app.main:app --reload`. Полные команды находятся в README.md.

## 7. Сценарии тестирования
| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Регистрация нового пользователя | HTTP 201 |
| 2 | Повторный логин | HTTP 409 |
| 3 | Вход с неверным паролем | HTTP 401 |
| 4 | Создание поездки с корректными датами | HTTP 201 |
| 5 | Дата окончания раньше начала | HTTP 422 |
| 6 | Просмотр чужой поездки | HTTP 404 |
| 7 | Добавление пункта вне дат поездки | HTTP 422 |
| 8 | Удаление поездки | HTTP 204, пункты удалены |
| 9 | Выгрузка CSV | Файл с поездками пользователя |
| 10 | Вызов admin API обычным пользователем | HTTP 403 |

Таблица описывает **сценарии проверки**, а не утверждает, что они уже были выполнены.

## 8. Заключение
Разработана структура учебного веб-приложения с разделением на модели, схемы, зависимости, API-маршруты и клиентский интерфейс. Реализована основная бизнес-логика планирования поездок. Перед защитой следует выполнить локальный запуск и тестирование, зафиксировать результаты и сделать скриншоты.
